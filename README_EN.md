# xfawaPL-exp

The experimental grammar and community idea lab for xfawaPL.

This is the experimental playground for "xfawaPL" (https://github.com/xfawa543/xfawaPL).

Have an idea for a syntax that you think xfawa should support? Put it here.

Whether it is a genuinely useful feature or a completely crazy idea, if it has a reasonable design possibility, it can be experimented with here.

---

## 🧪 What is this?

"xfawaPL-exp" does not represent the official syntax of xfawaPL.

The syntax found here is experimental. It may:

- Not be implemented yet
- Be under development
- Be under testing
- Be modified
- Be completely redesigned
- Eventually become part of the official language
- Or remain here forever

«A syntax appearing in "xfawaPL-exp" does not mean that it is supported by the official xfawaPL.»

---

💡 How do I submit a syntax idea?

You can submit your idea through a GitHub Issue.

It is recommended to include:

1. What is the syntax?

For example:

watch player.health {
    print(player.health)
}

2. What should it do?

For example:

«Execute the code block whenever "player.health" changes.»

3. Why is it useful?

For example:

«It provides an easy way to react to variable changes without manually polling the variable.»

4. How should it work?

If you already have an idea about its behavior, describe it.

For example:

«It should only execute when the value actually changes, rather than executing every frame.»

Don't have an implementation idea?

That's fine.

You can submit just the idea. The design can be discussed together.

🔬 Experimental Process

An experimental syntax will generally go through the following process:

Community Idea
      ↓
Design Discussion
      ↓
Added to the Experimental Repository
      ↓
Implementation
      ↓
Testing
      ↓
Real-world Usage
      ↓
Grammar Review
      ↓
┌───────────────────┐
│                   │
Accepted             Rejected
↓                    ↓
xfawaPL              Remains in exp
Official Syntax

An experiment is not guaranteed to succeed.

A syntax may turn out to:

- Conflict with existing syntax
- Be difficult to implement
- Have unclear semantics
- Be more complicated than the problem it solves
- Have poor performance
- Provide little practical value

In such cases, it may be rejected or redesigned.

---

🚦 Experimental Status

Experimental syntax may have one of the following statuses:

Status| Meaning
💡 Idea| An idea has been proposed, but has not been implemented
🔬 Experimental| Currently being experimented with
🛠️ Implemented| An implementation exists
🧪 Testing| Currently being tested
✅ Accepted| Approved and planned for the official language
❌ Rejected| Will not be included in the official language
🔄 Redesign| Requires further design work

---

🔢 EXP IDs

Experimental syntax may receive its own ID:

EXP-001
EXP-002
EXP-003
...

The ID is simply an experiment record number. It does not indicate the quality or importance of the syntax.

For example:

EXP-001 — watch
EXP-002 — defer
EXP-003 — ...

---

🧠 AI-Assisted Development

AI may be used during the design, implementation, and testing of experimental syntax.

For example:

Community Idea
      ↓
AI-assisted Design
      ↓
AI-assisted Implementation
      ↓
Human Review
      ↓
Testing

AI-generated designs or code do not automatically become part of xfawaPL.

Whether an experiment is accepted ultimately depends on project review and practical testing.

---

📜 Syntax Adoption Notice

Syntax designs, examples, implementations, and related discussions submitted to this repository may be modified, refactored, merged, or redesigned before being adopted by the official "xfawaPL" project.

Submission does not guarantee inclusion in the official language.

The final decision on whether a syntax is adopted, which parts are adopted, and what its final form will be is made by the "xfawaPL" project maintainer.

Once an experimental syntax is adopted into the official language, its final design may differ significantly from the original submission.
