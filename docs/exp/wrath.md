# wrath —— 修改已经发生的历史

`wrath`（暴怒）是一种实验性的"时间旅行赋值"。它和普通赋值最大的区别：普通赋值只能改变"现在/未来"，而 `wrath` 可以回头修改"已经发生的过去"，并让依赖那段历史的后续状态自动跟着变。

## 语法

```
wrath <变量名> = <表达式>
```

## 语义

`wrath x = R` 把 `x` 的历史值改成 `R`，然后**重新计算**所有（在 `wrath` 点之前）曾经直接或间接依赖 `x` 的变量，让它们也反映新的历史结果。

举例：

```
x = 1
y = x + 10

wrath x = 5

print(y)   // 15
```

`y` 当初是由 `x = 1` 推导得到 `11`。现在 `x` 的历史被篡改成 `5`，所以依赖这段历史的 `y` 必须重新计算为 `15`。这不是简单把 `x` 再赋值成 `5`，而是"过去被改写了，未来跟着被修正"。

## 多级依赖

依赖会沿链路传播：

```
x = 1
y = x + 10
z = y * 2
c = 100

wrath x = 5

// x = 5
// y = 15
// z = 30
// c = 100   （c 不依赖 x，不受影响）
```

## 外部副作用不会被改写

已经发生的输出属于"已经发生的副作用"，`wrath` 不会把它们"时间旅行回去改掉"：

```
x = 1
print(x)      // 输出 1，这个已经发生了，不会变

wrath x = 5

print(x)      // 输出 5，这里是新的状态
```

## RHS 正常求值

`wrath` 右边的表达式用你语言里普通的表达式规则求值，没有单独的求值器：

```
x = 1
y = 10
wrath x = y + 5   // x = 15
```

## 与 paradox 的关系

`wrath` = 改变过去 + **下游因果重新建立成功**；`paradox` = 改变过去 + **下游因果无法重新建立**，旧值无法被因果回收 → **GHOST**（值保留，因果状态丢失）。二者是同一个因果系统的不同结果。

对已 GHOST 的变量，一个后续的 `wrath x = v`（或普通 `x = v`）会赋予 `x` 新的因果来源（恢复 NORMAL）；`wrath` 重发的下游赋值若读取幽灵变量（纯表达式），则按方案 B 传播重新成为 GHOST。

## 实现位置

- Lexer：`wrath` 作为一个普通关键字。
- Parser：`wrath x = <expr>` 解析成 `WrathStatement`（AST 节点）。
- 变换：在 codegen 之前的 AST 变换阶段，把 `WrathStatement` 改写成一条普通赋值 + 按依赖顺序重新插入所有受影响变量的普通赋值。
- 复用现有变量系统：不重写 LLVM 变量机制，历史状态通过"重新执行依赖赋值"来体现。

## 目前限制（已知）

- 只在**直线代码**中支持依赖追踪。`wrath` 无法跨越控制流（if/while/循环块）去追踪变量依赖——进入这些块时会以"空白历史"开始。
- 依赖追踪建立在"变量 → 它定义时引用过的变量"上；重新赋值会让之前的依赖关系被新赋值覆盖（符合直觉的"最近一次定义生效"）。
