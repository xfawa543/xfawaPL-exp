# kill —— 行级杀手（让某一行从此不再执行）

`kill[N]` 把**源码第 N 行**"杀掉"：这条语句所在的源文件行之后永远不会再被执行（跳过不运行）。它是**运行时**的（编译后程序里有一个按行号索引的开关表）：

```
print("k1")        // 正常打印
kill[6]            // 杀 6 行（下面是 6 行的 print）
print("k2")        // 第 6 行 -> 永远不执行
print("k3")        // 正常打印
```

## 语法

```
kill[<行号>]
```

行号 1..1000000；`kill[0]` 与 `kill[999999]` 这类越界值**被忽略**（无害 no-op）。

## 语义

- **按"源文件行号"杀**：目标行号是本 `.xf` 源文件里的真实行号（含 `#test {` 行进制的 1 起）。
- **跳过意味着不运行**：一旦执行流到达被杀的语句，直接跳到下一句（不生成该语句任何副作用）。
- **全局且持久**：开关表在程序全程有效，杀死后任何函数里、任何循环迭代里、任何后续执行到达这一行都会被跳过。`kill` 一经设置不能撤销。
- **守卫放在每条语句上**：编译器给程序中每条语句都生成"查开关表 → 命中则跳过"的守卫，因此被杀的可以是普通语句、块内语句、循环体语句、函数体内语句都一样有效。
- **自身不算被杀**：`kill[N]`（N 为它自己所在行）在当次照常执行（守卫先于语句），把它目标行之后的执行杀掉；不存在"杀自己死循环"。
- **跨函数/循环**：`kill` 在函数 A 里杀掉函数 B 内部的某行，之后 B 再被调用时该行照样被跳过。

## 实现位置

- Lexer：`kill` → `KEYWORD_KILL`；Parser：`kill[N]` → `KillStatement`（存目标行号）。
- AST：`NodeType::KILL_STATEMENT`。
- Codegen：
  - 模块级全局 `[1000001 x i8] killFlags`（私有链接、零初始化），`kill[N]` 写入 `flag[N]=1`。
  - `codegen(Statement*)` 在每条语句入口生成守卫：`load flag[stmt.line]` → 命中则 `br` 到跳过块、未命中进入语句；语句执行完统一汇合到 continue 块（`come`/`repeat` 等控制流也包在里面，互不冲突）。
  - 行号取语句 AST 上的源文件行号。

## 边界说明（已定）

- 只按"行"粒度杀，不按"第几条语句 / 第几次调用"。
- 行号以源码原文行为准（注释、标点都算行）；编译器回显注释不影响行号分布。
- 杀不存在的行（比如整个文件没有那么大）无害。
- 开关一旦开启，程序内没有任何撤消手段（文档如此）。
