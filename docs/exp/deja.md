# deja —— 偷未来（预感）

`deja x` 往**未来**看一眼：如果 `x` 后面的直线代码里，第一个给 `x` 赋的值是常量（编译期可折叠），编译器就把它**提前**到 `deja x` 的位置可见。之后、真正赋值之前的每次读取 `x`，都是这个"预感值"。

```
fn need() { return 3 }

deja x
print(x)   // 42——预感到的未来值
x = 42
```

## 语法

```
deja <变量名>
```

## 语义：取第一个常量未来（方案 B）

`deja x` 在 `x` 所在语句块内，沿语句顺序**向前扫描**（直线代码），找 `x` 的第一条赋值语句：

- 第一个未来是常量 → 把 `deja x` **原地改写**成隐式 `x = <常量>`，从这时起读 `x` 就是预感值。
- 第一个未来**不是常量**（变量、函数调用、`input()`、浮点、数组、普通 o-literal 等）→ **预感失败**：
  - `deja x` 本身被丢弃；
  - 输出 warning（不报错，程序继续按常规语义执行）；
  - 之后的读取都是正常值。

方案 B = **只认第一个未来**，后续赋值不做多级追踪、不合并：

```
deja x
print(x)   // 5——第一个未来是 x = 5
x = 5
x = 6      // 不影响预感
print(x)   // 6——真正执行到这里，x 已被真实赋值
```

## 什么算"常量未来"

纯字面量或常量折叠可得的算术/比较表达式（不含函数调用、变量读取、幽灵/悖论状态）：

| 形式 | 示例 | 可预感 |
|---|---|---|
| 整数 / 布尔字面量 | `x = 42` / `x = true` | ✅ |
| 常量运算 | `x = 100 - 1` | ✅ |
| 一元正/反 | `x = -5` | ✅（负号常量折叠） |
| 变量 | `x = a` | ❌ |
| 函数调用 | `x = helper()` | ❌ |
| `input()` | `x = input()` | ❌ |
| 浮点 / 字符串 / 表达式引用幽灵状态 | — | ❌ |

## 扫描边界（不跨控制流、不跨函数）

预感是**直线代码**行为。向前扫描遇到以下任一情况立即刹车：

- 进入 `if` / `while` / `for` / `loop` 块
- 进入 `try {} expect {}` 的任一分支
- 进入 `lie` 块
- 到达函数边界

```
deja h
if true {
    h = 5     // 未来在 if 块内 → 不可预感
}
print(h)      // 5（运行时真实请求，不是预感）
```

```
deja w
w = helper()  // 函数调用 → 失败 + warning
print(w)      // 7（正常值）
```

```
deja v
v = need()    // main 里第一个未来是函数调用 → 失败
print(v)      // 3（正常值）
```

跨函数：`deja v` 只能"看"当前函数体内的未来。别的函数里 `v = 7` 与 `main` 的 `deja v` 无关。

## 副作用：未来赋值照常执行一次

`deja` 是**把未来的常量值提前可见**，不是把未来赋值搬走，也不重跑任何调用。真实赋值语句仍然执行且只执行一次：

```
deja m
print(m * 2)   // 200——预感 100
m = 100        // 照常执行一次
print(m)       // 100
```

## 与 wrath / paradox 的关系

三者在**变换顺序**上各自独立、正交：

- `wrath`：改历史 → 下游重新建立；
- `paradox`：改历史 → 下游成 GHOST；
- `deja`：看未来 → 把常量未来提前可见（不改变任何已有赋值）。

```
q1 = 1
q2 = q1 + 10
wrath q1 = 5
print(q2)     // 15
deja q3
print(q3)     // 9——预感不受 wrath 影响
q3 = 9
p1 = 1
p2 = p1 + 1
paradox p1
print(p2)     // 2#（paradox 生效）
deja p3
print(p3)     // 8——预感不受幽灵状态影响
p3 = 8
```

## 实现位置

- Lexer：`deja` → `KEYWORD_DEJA`。
- Parser：`deja <name>` → `DejaStatement`（记录名字与位置）。
- AST：`NodeType::DEJA_STATEMENT`。
- 变换：`applyDejaTransform`（在 wrath/paradox 变换**之后**运行）。`dejaBlock` 逐块扫描，`isDejaConstantExpr` 判定常量、`isDejaBoundary` 判定刹车；成功 → 原地改写为普通赋值（`isReassignment=false`，在 deja 位置隐式诞生，真实未来赋值复用同一 alloca 覆盖）；失败 → 丢弃该语句 + warning。
- Codegen：`DejaStatement` 本身不生成代码（变换后已不存在或已成为普通赋值）。
- warning 文案：`[deja] 无法预感 <x> 的未来值（未来赋值不是常量），保持常规语义`。

## 目前限制（已知）

- 只认**第一个**未来且必须是**常量**（方案 B）：多级依赖、非常量未来一律不追。
- 扫描不跨 `if`/`while`/`for`/`loop`/`try_expect`/`lie` 块和函数边界。
- 常量判定不含浮点、字符串、数组、普通 o-literal 及涉及幽灵/悖论状态的表达式。
- `deja` 改写为普通赋值后，受与普通裸赋值相同的现有语言约束（例如跨函数共享声名集合 / 控制流块内先声明再在外层重赋值的历史行为，见测试注释）。
