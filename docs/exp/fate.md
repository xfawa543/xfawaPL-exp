# fate —— 设定命运，反抗后只能被不完美地拉回

`fate x = 100` 给 `x` 设定一个**命运值**（并把 `x` 立即设为该值）。从这一刻起，`x` 仍然可以被**正常赋值**——这不报错，也不禁止。但每次赋值一旦离开命运值，命运机制就会立刻把 `x` **不完美地拉回**：

- 结果**朝命运值方向**移动（当前值与命运值的"中点折半"）；
- 永远**不等于命运值**（有误差，这是机制本身的一部分）；
- 每一轮恢复结果如果成为恢复史上到达过的**最大值**，就成为**新的『底数』**；后续任何恢复都**不能低于底数**。

一句话：你可以反抗命运，但命运会一直试图把你拉回来；而你反抗留下的痕迹，会让命运再也没有办法把你完美地恢复。

```
fn main() {
    fate a = 100
    print(a)        // 100——命运值（出生时立即可见）
    a = 20          // 反抗！
    print(a)        // 60——被拉回：20 + (100 - 20)/2
}
```

## 语法

```
fate <变量名> = <表达式>
```

`<表达式>` 的求值结果就是命运值（同时把变量设成它）。

## 恢复规则（可精确复现的确定性算法）

每次对命运变量赋值 `x = v` 之后，如果结果**偏离命运值** `D`，就从当前值 `v` 出发执行一次恢复；如果赋值恰好等于命运值，则**不恢复、不位移**。

单次恢复（全部用有符号 64 位整数运算，位移除向零截断）：

```
mid0    = v + (D - v) / 2            // 朝命运值折半
if mid0 < floor:                     // 结果会掉到底数以下？
    mid0   = floor + (D - floor) / 2 // 改为从底数向命运值折半
    if mid0 < floor: mid0 = floor    // 无论如何不低于底数
result  = mid0
```

底数更新（**持久存在**，不是每次恢复重算）：

```
if result > floor: floor = result    // 本轮的恢复结果成为新的底数
```

之后任何恢复结果都不能低于这个 floor。

## 走势示例

```
fate b = 100
b = 20       // 60（恢复 1；新底数 = 60）
b = 10       // 80（恢复 2；20 掉到 10，但底数 60 → 80）
b = 20       // 90（恢复 3；同幅度的反抗，在底数抬升后也跟着被抬高，不会回落到 60）
b = 30       // 95（恢复 4；逐步逼近 100，但永远不等于 100）
```

```
fate c = 100
c = 20       // 60（新底数 60）
c = 10       // 80（新底数 80）
c = -100     // 90 —— 深反抗：mid0 = -100 + 200/2 = 0，低于底数 80，
             //        于是从底数向命运值折半：80 + 20/2 = 90（不小于底数，90 成新底数）
```

## 语义要点

- **不禁止反抗**：`x = 20` 是合法赋值，不是错误、不是警告、不是 const。
- **不是直接回设**：恢复从不把变量直接设回命运值。
- **有历史**：底数持久保存，只有上升、不会下降（`floor` 会精确记录每一轮恢复的结果上限）。
- **普通变量不受影响**：没有 `fate` 声明的变量行为完全不变。
- **恰好命中命运值**：`x = D` 保持 `D` 原样，不动 floor。
- **非整数命运值**（字符串、浮点、数组）：退化为普通赋值，并输出一条 `[fate]` warning——命运机制只作用于整数变量，绝不破坏正常语义。

## 实现位置

- Lexer：`fate` → `KEYWORD_FATE`。
- Parser：`fate <name> = <expr>` → `FateStatement`（记名 + 表达式）；变量名同时登记进声明集合，保证后续裸赋值解析为重赋值（不会重复声明）。
- AST：`NodeType::FATE_STATEMENT`。
- Codegen（LLVM，**纯代码生成实现，不做 AST 变换**）：
  - `codegen(FateStatement*)`：诞生/复用变量的 alloca，把命运值存入变量，并在 entry block 分配两个 i64 alloca——`destiny` 与 `floor`（初始为 `INT64_MIN` 表示"未设置"），登记进每函数的 `fateSlots`。
  - `codegen(AssignmentStatement*)` 在完成赋值 `store` 之后检查 `fateSlots`：命中的变量立刻执行恢复（`__xfawa_fate_recover(i64 cur, i64 dst, ptr floor)`，模块内 InternalLinkage 辅助函数）。
  - `fateSlots` 与 `locals` 一样按函数作用域清空/保存/恢复（`codegen(Function*)` 与按钮处理器）。
  - 恢复运算全用 i64 有符号（sdiv），必要时对变量 alloca 宽度做 sext/trunc 转换。

## 目前限制（已知）

- 命运恢复只作用于**整数变量**（默认 `int`/`long`/`bool` 的实际存储宽度）；浮点、字符串、数组的命运值退化为普通赋值 + warning。
- `fate` 状态是**函数局部**的：换个函数内同名的变量不会共享底数。
- 命运值的表达式若是运行时值（函数调用、`input()` 等），使用该值作为去向依然生效，但没法在编译期预览。
- 底数永不下降，也无法手动清除（这正是设计意图）。
