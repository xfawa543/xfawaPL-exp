# `?!` —— 随机二元运算符（谜之运算）

`a ?! b` 在**运行时**从"对 `a` 和 `b` 的类型都合法、且结果类型一致"的二元运算集合里**随机挑一个**并真正执行。同一条 `a ?! b` 每次执行都可能得到不同的运算结果：

```
a = 6
b = 2
print(a ?! b)   // 本次运行可能打印 8（+）、4（-）、12（*）、3（/）、0（%）、2（&&）、6（||）中的任意一个
```

`?!` 是 `¿`（倒问号）的 ASCII 替代写法；语义一致，当前只支持 `?!`。

## 语法与优先级

```
<表达式> ?! <表达式>
```

`?!` 是**二元运算符**（不是关键字、不是函数），优先级最低——比所有算术/逻辑运算符都低：`a + b ?! c` 先算 `(a+b)`，再对 `(a+b)` 和 `c` 做随机运算。

## 随机时机

- **运行时时点**：每次执行到 `a ?! b` 时重新随机（不是编译期挑定一次）。
- 随机由 C 库 `rand()` 完成：程序首次使用 `?!`（或 `...`）时在函数入口处按 `time() ^ GetTickCount()` 播种一次（因此同一秒内重跑结果也几乎必然不同），之后每次 `?!` 取 `rand() % N` 从候选集中选一个运算。
- 循环里多次执行 `a ?! b` 会得到不同的随机结果。

## 候选运算集合（按操作数类型过滤）

编译时（实际上是 codegen 阶段按已产出的操作数类型）先筛出合法候选，再限定为**结果类型一致**的那一组。比较类（`== != < <= > >=`）的结果是布尔（i1），与数值/逻辑组的结果类型不一致，因此**一律不进入候选集**（见"结果类型"）。

| 操作数类型 | 候选运算（按此固定顺序） | 结果类型 |
|---|---|---|
| `int ?! int`（i32/i64，宽窄皆可） | `+  -  *  /  %  &&  \|\|` | 整数（必要时加宽到较长宽度） |
| `float ?! float` | `+  -  *  /  %` | float |
| `int ?! float`（混合数值） | `+  -  *  /  %` | float（整数自动提升） |
| `bool ?! bool` | `&&  \|\|` | int（0/1，与 `true && false` 结果一致） |
| 其它（字符串、bool 与数字混用、数组等） | **无候选** | 见"退化为左操作数" |

> 关于"位运算"：本语言没有单字符 `&`/`|`；这里的 `&&`/`||` 是**非短路**的 AND/OR，对整数就是位与/位或，因此同时充当逻辑与位运算候选。

## 结果类型

`?!` 从不破坏静态类型系统：

- 同一候选组内的每个运算产出的 LLVM 类型**完全一致**（整数组全是整数、浮点组全是 float、布尔组是 0/1 的 int）——随机选哪一个都不会改变表达式的静态结果类型。
- 比较类被排除，正是为了保证这一点：数值 `?!` 数值永远不会神不知鬼不觉地冒出布尔结果。
- 结果可用在任何需要该类型的上下文（赋给变量、参与算术、print 等）。

## 退化为左操作数（没有合法候选）

当左右操作数类型没有合法候选集（典型：字符串参与，或 bool 与数字/浮点混用）时：

1. 编译期输出一条 `[?!]` warning："没有合法候选运算，?! 退化为左操作数"；
2. 表达式在运行时**确定性地**求得左操作数的值（右操作数完全不被使用）。

这是有意设计的兜底：字符串唯一的二元运算是拼接（单候选，没有随机意义），所以字符串不参与随机；不支持的组合用一个确定、可测、类型安全的规则收尾。

## 与其它 EXP 的关系

`?!` 的随机性共享现有 `rand()`/`...` 随机基础设施（`getRandFunction()`、`emitRandomCallSeedOnce()`、`usesRandomBuiltin`）；候选运算的运算语义与普通二元运算符完全一致（除法/取余除以 0 的运行时行为也与普通 `/`、`%` 相同）。与 fate/envy/deja 等的逐次状态互不干扰。

## 实现位置

- Lexer：`?!` → `PUNCTUATOR_BANG_QUESTION`（两字符最长匹配，不与 `!` / `!=` 冲突）。
- Parser：`parseExpression()` 里最低优先级循环 → 复用 `BinaryOp`，`BinaryOpType::BANG_QUESTION`。
- Codegen：`codegen(BinaryOp*)` 开头分派给 `codegenRandomBinaryOp()`——按操作数 LLVM 类型选定候选组，直线计算全部候选值，`rand() % N` + `select` 链选一；无候选 → `[?!]` warning + 返回左操作数值。
- 语义分析/转译/注释：`BinaryOp` 通配处理；transpiler 输出 `?!`。
## 目前限制（已知）

- 不支持比较类候选（结果类型一致性要求，见上）。
- 不支持字符串/数组/"bool 混数字"的随机（无候选 → 退化为左操作数）。
- 数值溢出/除零行为与对应普通运算符一致（`/`、`%` 遇除数为 0 是运行时未定义行为；测试避免 0 除数）。
- `rand()` 是 C 库伪随机：不适用于加密/抽奖等需要真随机的场合。

## 测试

- `tests/exp/test_randop.xf` — t1 两整数（结果集 {0,2,3,4,6,8,12}）；t2 两浮点（{0.5,3.25,4.5,8.5,13.0}）；t3 两布尔（{0,1}）；t4 int×float（混合数值提升为 float，{0.5,1.2,5.5,7.5}）；t5 无合法候选（字符串三者 → 退化 abc/5/abc）；t6 结果类型不兼容上下文（5 ?! 3 永不出现比较类独占结果 0）；t7 同一表达式多次执行（10 ?! 6 每次都在 {1,2,4,14,16,60} 内）。
- `tests/run_randop_tests.ps1` — 编译断言 ≥3 条 `[?!]` warning；运行时按小节校验：每个采样都落在合法候选结果集内、且累积去重 ≥2（证明并非固定在单一运算符）。
