# `drift` —— 递归随机参数（左右横跳递归）

`drift` 是**函数声明修饰符**：用 `drift` 修饰一个函数后，函数体内的**递归自调用**不再原样传递你写下的实参，而是每次执行时**按该参数的类型和随机范围现算一个新的随机值**传进去。函数第一次被外部调用时，仍然严格传递调用点写下的原值。

它不是 `rand()`/`rnd()` 的语法糖，而是对"递归行为"本身的改造：**递归的下一步走哪条路由随机决定**，同时内置深度上限保证任何情况下都能终止。

```
drift(-5, 5) fn wander(n) {          // 每次自调用 n 都从 [-5, 5] 里重新随机
    print(n)
    if (n <= 0) return 42            // 随机命中 ≤0 就按原样自然返回
    return wander(n)                 // 自调用：参数被随机覆盖，写的 n 被忽略
}

fn main() {
    print(wander(3))                 // 外部调用：传原值 3，第一个打印的就是 3
}
```

## 语法

```
drift fn f(参数...) { ... }                       // 用默认随机范围
drift(lo, hi) fn f(参数...) { ... }               // 自定义随机范围（含负数/小数）
drift(depth: N) fn f(参数...) { ... }             // 自定义递归深度上限
drift(lo, hi, depth: N) fn f(参数...) { ... }     // 范围 + 深度一起写
```

- `lo` / `hi` 可以是整数或小数，也支持负数（如 `drift(-5, 5)`）。
- `depth: N` 必须紧跟数字且 `N >= 1`。
- 空写 `drift()` 是错误。
- `drift` 之后必须跟 `fn`（修饰函数声明）。

## 随机时机

- **仅自调用生效**：只有当调用点是该函数自己（解析到同一个函数符号）时，实参才会被随机覆盖。
- **外部调用不变**：main 或其它函数调用它时，写什么传什么（`wander(3)` 传给函数的就是 3）。
- **运行时每次重新随机**：同一函数被多次递归时，每次自调用都重新调用一次 `rand()` 生成参数，不是编译期挑定一次。
- 随机由 C 库 `rand()` 完成，程序启动时（main 入口）按 `time() ^ GetTickCount()` 播种一次。

## 随机规则（按参数类型）

| 参数类型 | 随机生成方式 | 默认范围 |
|---|---|---|
| `int` / `long` | `lo + rand() % (hi - lo + 1)` | `[0, 100]` |
| `float` | `lo + (rand() / 32768.0) * (hi - lo)` | `[0.0, 1.0)` |
| `bool` | `rand() & 1` | `{0, 1}` |
| `string` | **不支持**（编译错误，见下） | — |

自定义范围时，`drift(lo, hi)` 的整数与浮点写法都可：`drift(-5, 5)` 对 int 参数生成 [-5,5]；对 float 参数生成 [-5.0, 5.0)（同一范围按参数类型的精度解释）。

## 递归深度上限（必需的终止机制）

随机递归靠深度上限兜底，任何情况下都能停下：

- 内置默认上限：**1000** 层。
- `drift(depth: N)` 可覆盖为更小的值。
- 当递归链深度到达上限，下一次自调用被**跳过**，并按调用处的类型求值为 0（`float` 为 `0.0`，`bool` 为 `false`，其它为整数 0），整个链条随即正常收尾。
- 没有 `depth: N` 的 `drift fn` 若随机值达不到你写的终止条件，也会在 1000 层时被截断并返回 0，不会无限递归。

## 原有终止条件仍然有效

函数里原本写的终止判断（`if (n <= 0) return 42` 之类）照常生效：每次自调用随机出的值一旦命中终止条件，该帧像普通递归一样返回，整条链路把返回值原样传回。只有当随机连续"打偏"到深度上限时才走 0 兜底。

注意：要让返回值传回调用者，自调用应当作为返回值使用——写成 `return wander(n)`，而不是单独一条 `wander(n)` 语句（独立语句的返回值会被丢掉，函数就会落到隐式的 `return 0`）。

## 多参数

`drift` 对每个参数**独立**随机：`drift(-5, 5) fn f(a, b)` 的每一次自调用，`a`、`b` 都在 [-5,5] 里各自随机一次，互不相关。

## 参数类型推导与编译错误

编译器在编译期推断每个参数的随机类型，规则：

1. 优先用函数**体内**对参数的用法推断（`n + 1` → int、`n < 0.5` → float）。
2. 否则取**所有调用点**（外部调用 + 自调用）实参类型的并集，只有并集里恰好出现一种具体类型时才采用。
3. 两种情况都得不出具体类型时，参数保持"未知"。

错误（带 `[drift]` 标记，编译失败）：

| 场景 | 错误信息关键词 |
|---|---|
| 参数是 string（自调用要随机它） | `[drift] cannot randomize parameter` |
| 参数类型完全无法推导 | `[drift] cannot infer` |
| 自调用参数个数与函数定义不符 | `[drift] recursive call ... has N argument(s)` |
| `drift(hi, lo)` 下界 > 上界 | `[drift] range lower bound is greater than upper bound` |
| 离散范围太大（超过 int64） | `[drift] int range width is too large` |

因为随机生成的 LLVM 参数类型与函数签名、局部变量、调用点必须一致，字符串（指针）和"根本不知道是什么类型"的参数无法安全随机，所以直接编译报错。

## 与其它 EXP 的关系

- 阅读 `randop.md` / `ellipsis.md` 了解类随机基础设施。
- `drift` 与 `?!`、`...` 共用同一个 `rand()` 流；各自状态互不干扰。

## 目前限制（已知）

- 不随机"外部调用"，只随机递归自调用（设计如此）。
- 不支持字符串参数。
- 未声明的类型 / 无法推导的类型会编译报错而不是用 i64 猜。
- 嵌套多个 drift 函数的递归共享同一个全局深度计数器，最坏会低估可递归深度（靠各自较松的 `depth: N` 或默认 1000 兜住），不会死循环、不会溢出错乱。
- `rand()` 是 C 库伪随机：不适用于加密/抽奖等需要真随机的场合。
